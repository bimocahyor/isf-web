# ADR-002: Database — PostgreSQL

**Status:** Accepted
**Date:** 2025
**Updated:** 2026 — confirmed PostgreSQL 18.6 stable available on Docker Hub; updated from 17 to 18.6-alpine

## Decision

PostgreSQL 18.x is the single relational database for all persistent data.

## Rationale

| Requirement | PostgreSQL Feature |
|-------------|-------------------|
| Financial ledger integrity | ACID transactions, constraints, CHECK constraints |
| Monetary values without rounding | `NUMERIC(15,2)` — never FLOAT |
| Timestamps with timezone | `TIMESTAMPTZ` — stored as UTC, displayed per-locale |
| Flexible metadata and snapshots | `JSONB` columns for revision history, webhook payloads, audit state |
| Non-enumerable primary keys | `UUID` (gen_random_uuid()) — reduces IDOR risk |
| Enum enforcement | PostgreSQL native ENUMs for status fields |
| Soft deletes | `deleted_at TIMESTAMPTZ` convention |
| Full-text search | Built-in FTS — no Elasticsearch needed at this scale |

## Schema Conventions

### Primary Keys
All tables use UUID primary keys generated by `gen_random_uuid()` (pgcrypto).
Reason: non-sequential IDs reduce the risk of IDOR attacks via ID enumeration.
Note: UUID alone is NOT sufficient IDOR protection — explicit ownership checks are required.

### Timestamps
- `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()` — on all tables
- `updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()` — on mutable tables; use a trigger to auto-update
- `deleted_at TIMESTAMPTZ` — for soft-deleteable entities
- `updated_at` must NOT be added to immutable financial journal rows

### Monetary Values
```sql
-- CORRECT
amount NUMERIC(15,2) NOT NULL

-- FORBIDDEN — introduces floating-point rounding errors in financial arithmetic
amount FLOAT NOT NULL        -- never
amount REAL NOT NULL         -- never
amount DOUBLE PRECISION NOT NULL  -- never
```

### Soft Deletes
Do not hard-delete user accounts, applications, financial records, or audit logs.
Use `deleted_at TIMESTAMPTZ` for soft deletion.
Filter soft-deleted records with `WHERE deleted_at IS NULL` in queries.

### Financial Records — Special Rules
Journal entries (journal_lines, journal_transactions) must NEVER be:
- Updated after posting
- Soft-deleted
- Hard-deleted

Corrections use reversal transactions only (see ADR-009).

## Migration Strategy

- All schema changes are applied via Drizzle Kit generated SQL migration files.
- Migration files are versioned, committed to the repository, and reviewed like code.
- Migrations are run automatically on deploy.
- Never modify a live schema by hand.
- Never edit a migration file after it has been applied to any environment.

## Local Development

PostgreSQL runs in Docker (see `docker-compose.yml`).
Database connection is configured via `DATABASE_URL` environment variable only.
No credentials are hard-coded anywhere in source code.

## Backup Requirements (Production — Phase 7)

- Managed PostgreSQL with automated daily backups
- Point-in-time recovery (PITR) capability
- Backup retention: minimum 30 days
- Encrypted backups at rest
- Regular restore testing
- See `docs/deployment/backup-strategy.md`
